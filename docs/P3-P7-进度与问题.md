# P3-P7 进度与问题（2026-09-10，含两大 bug 根因修复）

## 一、两个已报告问题的根因与修复

### 1. 「PDF 全是图片、无法选中文字 / 做行内批注」—— 阅读器文本层塌缩

**现象**：打开 PDF 只看到画布（像图片），选中不了文字，无法选中发送给 AI。

**根因**（已用 Electron DOM 实测证实，非 PDF 本身问题）：
- 下载的 arXiv PDF 有完整文本层（Node 提取第 1 页 1368 字符正常）。
- pdfjs-dist v5 的 `TextLayer` 依赖 CSS 变量做布局：`setLayerDimensions` 把容器尺寸写成
  `calc(var(--total-scale-factor) * …px)`，span 字号是 `calc(var(--total-scale-factor) * var(--font-height))`。
  官方 viewer 由 `.pdfViewer .page` 提供 `--scale-factor / --total-scale-factor / --user-unit / --scale-round-*`，
  而本应用是**裸 `.textLayer` div**，这些变量全部缺失。
- 实测对比（scale=1.4，595×842pt 页）：
  | 指标 | 缺变量（原代码） | 补变量（修复后） |
  |---|---|---|
  | 文本层高度 | 587px（塌缩） | 1178px（正确） |
  | span 字号 | 16px（错位） | 20.09px（正确） |
  | 文本位置 | 与画布错位 | 精确对齐 |

**修复**（`src/renderer/pages/ReaderPage.tsx`）：构造 TextLayer 前在容器上设置
`--scale-factor`、`--total-scale-factor`（= scale）、`--user-unit:1`、`--scale-round-x/y:1px`。

### 2. 「解析的摘要有很多乱码」—— arXiv 摘要/LLM 总结里的 LaTeX 记号

**现象**：检索结果摘要出现 `$W^{+}\rightarrow{D^{+}_{s}γ}$` 这类「乱码」；AI 总结里夹杂 `\(B^\pm \to …\)`。

**根因**：不是编码问题（DB 里存的总结本身是干净 UTF-8），而是 **arXiv 摘要以 LaTeX 数学源码形式返回**，
AI 总结也爱输出 LaTeX 定界符，直接展示就像乱码。

**修复**：
- 新增 `src/shared/latex.ts` `latexToText()`：剥 `$…$ / \(…\) / \[…\] / \begin{…}`，转换常用宏
  （希腊字母、箭头、`\frac`→(a)/(b)、上下标→ᵃⁱ⁰₁₂₃、`\mathrm{}` 等），8 条单测全绿。
- 检索页标题/摘要、阅读器总结展示（流式+历史）统一经 `latexToText` 渲染。
- 总结 prompt 增加「数学公式一律纯文本（如 γ、x²、B±→D），禁止 LaTeX」约束，从源头减少。

### 附带修复：Semantic Scholar 限流静默失败
`search()` 现在返回 `{hits, warnings}`，S2 429 限流（实测常见）时检索页显示黄条提示，

## 六、AI 助手「多次触发、重复回复」修复（2026-09-11）

**现象**：一条消息发出后，AI 回复出现多条且内容重复、越来越长（工具调用场景明显）。

**根因**（代码级确认，非 UI 重复订阅）：
- dsh 会话语义：一次用户消息 = 1 个 turn，turn 内可跑多个 step（每步一次 LLM 调用，工具循环时常见）。
- **每个 step 都以 `assistant/chunk` 的 `finish` chunk 结束**，并紧随一条 `assistant/message`（dsh 组装好的该 step 完整消息，含 text/reasoning blocks）。
- 旧实现 `agentService.handleEvent` 在**每次收到 `finish` 时把「跨 step 累积的 st.text」落库**：step1 finish 落 A，step2 的增量继续追加进 st.text 后 finish 又落 A+B → DB 与 UI 出现重复且越来越长的回复。

**修复**：
- `agentHost.ts`：新增 `assistant/message` 事件解析（每 step 一条，text/reasoning 分开），作为唯一可靠的落库来源。
- `agentService.ts`：`finish` 不再落库（只清 UI 流 + 清空累积），`assistant-message` 负责落库。
- 单测新增 2 条（agentService.spec.ts 共 5 条）：多 step 各自落库不累积、finish 后无 message 不落半截。
- **真实 dsh 端到端验证 PASS**：跑一场 5-step 工具循环（glob→读数→总结），落库 5 条独立 reasoning + 3 条独立 text，零前缀重复。

**验证**：47/47 单测全绿；tsc 通过；真实引擎 E2E 通过。
